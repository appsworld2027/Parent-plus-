## Working first slice

- `/parent`: separate dark Aurora header, family navigation, white selected child chips and floating Home/Week/Log/Together/Explore navigation. Shared local Bricolage Grotesque font is self-hosted with its OFL licence; decorative Aurora artwork comes from the supplied reference. Native React Native components render the UI; there is no HTML/WebView wrapper.
- Same Supabase project/public connection key and Auth account credentials as Coach. Parent sign-in verifies the session/email, skips academy creation and loads an independent family workspace. Signup/recovery reuses existing `/auth` callback routes, with a non-secret per-tab Parent return intent; no new auth service or duplicate account is required. Coach's existing auth flow remains the default `/` entry.
- Family setup; add/edit child name, optional birthday and colour; switch children. One family owner in this first release. Family child IDs are distinct from academy student IDs.
- Real saved family plans/events, reminders and private text memories/together-time logs. Week totals come from the selected child's saved records, not prototype sample metrics. Suggestions are a static activity catalogue; time is added only after the parent explicitly logs it. Family data is not shared back to a coach.
- Explicit coach invitation: issue a student-specific code from the Coach profile; Parent reviews the academy/student identity and selects an owned family child before confirming. No name, phone or email auto-matching.
- Only coach-reviewed per-child feedback appears in From coaches. Parents cannot query private observations, unreviewed versions or another family's feed. Selected class photos/videos can be opened through short-lived private access only while permission for every identified subject remains valid.
- Linked parents can record photo/video/sharing decisions in Parent. Their account-based refusals cannot be raised by a Coach attestation. No permission is preselected on the first connection. This verifies the signed-in account and coach-issued invitation, not an independent legal-guardian identity document.

Parent native components are reusable for a future separately packaged Android app; the current Parent deliverable is the mobile web workspace, not a separate verified Parent APK.

Update012 adds `parent_families`, `family_children`, `family_moments`, `family_todos`, `family_events` and `parent_coach_links`. Family tables enforce owner RLS and child/family composite foreign keys. A coach does not gain access to family data by owning an academy; parent membership does not grant access to the academy's roster, contacts, ledger or raw observations. The same person may deliberately use the same Auth account for both roles, with ownership checked independently.

Invitation hashes live only in a restricted private table. Codes use two secure random UUIDs (244random bits), SHA-256 at rest,48-hour expiry, revocation of older unused codes and one-time consumption. Exact same-parent/child claim retries return the existing active connection. Issuance/claims/reviews/disconnects serialize on the academy lock. Initial scope is one active family owner per academy student; multiple connected coaches per family child are supported. A disconnect cancels old approvals so a replacement family does not inherit them. A stale disconnect for an inactive old link has no effect on a replacement family's later approvals.

A reviewed handoff is `awaiting_parent_link`, `available_to_parent` or `cancelled`. Approval makes it available immediately if a verified invitation link already exists. Claiming a new link releases prior approved holds; fresh default-deny Parent media choices can still withhold media-bearing feedback until permitted. `parent_feedback_feed` returns only the permitted per-child snapshot. Parent media reads require that snapshot, active link/child, finalised media and current capture/sharing consent for all subjects. Public URLs are never stored. Preview URLs expire after60seconds; already issued URLs/browser caches are not instantly revoked.

A new connection starts its guardian media choices at false. Parent permissions are recorded with source `parent_account`; Coach declarations use `coach_attestation`. Parent reads of permission state are whitelisted RPC results, not access to other guardians' private evidence/history. Revoking a media purpose cancels affected active handoffs, including a group image shared for another child. Text-only feedback does not require media permission. A former disconnected guardian cannot alter the new family's link or permissions.

The Parent feed is refreshed on page load/reload or explicit Refresh. This is in-app feedback availability, not a device push notification, email/WhatsApp delivery or read receipt. Native OS push, push workers, read receipts and real guardian-to-coach messaging are not built.
