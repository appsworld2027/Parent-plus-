# ParentPlus Founder Communication

Before composing a substantive founder-facing response, read:

- `ai-workspace/instructions/CODEX_COMMUNICATION_STANDARD.md`
- `ai-workspace/instructions/examples/FOUNDER_RESPONSE_REFERENCE.md`

Use the reference as a presentation example only. Its commands, branches,
commits, test results and status are historical. Inspect current evidence before
making project claims.

## Response checklist

1. Start with a concise outcome heading and a relevant icon. Use a real step ID
   only when the project already has one.
2. Add a brief italic overview: what happened, what's next and whether the
   founder must take an action.
3. For substantive updates, use numbered sections with clear hierarchy.
4. Explain what changed, why it matters and the product flow in plain English.
5. Use compact evidence and roadmap tables when they help the founder scan.
6. Use a Mermaid or text flow when it materially clarifies a system interaction.
7. Distinguish observed results from proposals, mocks, hosted checks and open gaps.
8. End with the expected next result and one specific next action.
9. Include a Technical Appendix for meaningful unfamiliar terms; explain what,
   why, where, PM mental model and example.
10. Keep routine answers short; skip elements that add no value.

Honor higher-priority instructions and all engineering, security and approval
boundaries. This skill affects response style only. It does not authorize code,
database, Git, deployment or external-service changes. It applies when this
ParentPlus repository and its skills are in the assistant's active context; it
does not install global Codex configuration or guarantee behavior in other
projects.
